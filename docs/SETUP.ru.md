# Сборка и настройки

[← Herdr Tavern](../README.ru.md) · [English](SETUP.md) · Русский

## Требования

- **macOS 14 или новее.** Сборка рассчитана на архитектуру текущей машины, не является универсальной.
- **Xcode Command Line Tools** с `xcrun swiftc`.
- **Rust stable и 1.96.1 через rustup**, Cargo.
- **Zig 0.16.0** в `PATH` или путь к исполняемому файлу в `ZIG`; **Python 3** для упаковки текстов лицензий зависимостей.
- **Локальный сертификат подписи** — настройка описана ниже.

Приложение включает изолированный runtime `herdr-tavern`. Сами программы агентов и доступ к моделям настраиваются отдельно. Генератор изображений не нужен.

Все поставляемые шрифты включены в `resources/Fonts/` и копируются при сборке в `.app` без скачивания шрифтов или чтения локально установленных. Tavern загружает их из ресурсов при запуске; ручная установка шрифтов не нужна. Терминал использует Iosevka Custom **34.9.0** (девять весов от Thin до Heavy с настоящими Oblique) и Symbols Nerd Font; декоративные интерфейсные шрифты также входят в комплект. Системные резервные шрифты Menlo и emoji по-прежнему предоставляет macOS.

## Локальная подпись

До первой сборки создай в **Keychain Access** самоподписанный сертификат **Herdr Tavern Local Signing** типа **Code Signing**. Он должен иметь приватный ключ; настрой доверие только для Code Signing и разреши `/usr/bin/codesign` использовать ключ. Без пригодного сертификата сборка останавливается до компиляции.

Сохраняй этот сертификат при обновлениях: пересоздание даже с тем же именем меняет идентичность приложения и может потребовать повторно выдать разрешения macOS. Приватный ключ и его экспорт не должны попадать в репозиторий. Локальная подпись не заменяет Developer ID и нотариализацию публичного релиза.

## Сборка и запуск

Выполняй команды из корня репозитория, не из `docs/`:

```sh
./build.sh
open "build/Herdr Tavern.app"
```

Первой сборке может понадобиться сеть для загрузки Cargo- и Zig-зависимостей. При заполненных кэшах для Cargo можно использовать `CARGO_NET_OFFLINE=true`. Скрипт собирает приложение и встроенный runtime и проверяет их подписи, но не запускает тесты.

Сборка использует сохранённые runtime PNG и не требует генерации изображений. Новый bundle собирается в чистом временном каталоге и заменяет `build/Herdr Tavern.app` только после успешной компиляции, подписи и её проверки. Художественные мастера и рецепты подготовки в bundle не входят.

В release-профиле Cargo явно задано `strip = "none"`: это обходит [ошибку LLVM при удалении debug-информации из dylib](https://github.com/rust-lang/rust/issues/157750), из-за которой macOS 27 отказывается загружать Rust proc-macro с `mis-aligned LINKEDIT string pool`. Обезличивание путей при этом сохраняется.

При сборке локальные пути исходников, домашнего каталога, Cargo и инструментов Rust заменяются относительными префиксами в приложении, включая отладочную карту линкера. Доступ к файлам во время работы не меняется; происхождение ресурсов обозначается именами исходных наборов и артефактов, а не личными путями.

## Встроенный runtime

Сборка компилирует `vendor/herdr/` и помещает бинарник в `Contents/Helpers/herdr-tavern`. При запуске нет загрузки или поиска upstream `herdr`. Отсутствие встроенного бинарника — ошибка упаковки; нужно переустановить полное приложение Tavern.

Runtime использует `~/.config/herdr-tavern/` (внутри `XDG_CONFIG_HOME`, если задан), отдельные сокеты и переменные `HERDR_TAVERN_*`. Существующие конфигурация и сессии upstream не переносятся. Каталог Helpers стоит первым в PATH новых панелей, поэтому команда `herdr-tavern` доступна в них без системной установки.

Tavern подключается к своему работающему серверу либо запускает встроенный runtime, если сервер не слушает. Режим `--socket` никогда не запускает сервер и не удаляет сокеты. Журнал запуска: `~/Library/Logs/HerdrTavern/server.log`. Runtime обновляется вместе с Tavern, не через updater upstream.

## Выбор сессии и сервера

Для отдельной сессии выполни из корня репозитория:

```sh
"build/Herdr Tavern.app/Contents/MacOS/HerdrTavern" --session tavern
```

| Аргумент | Назначение |
| --- | --- |
| `--session NAME` | Выбрать именованную сессию herdr-tavern. |
| `--herdr-tavern PATH` | Выбрать явный путь к собственной сборке runtime для разработки; неверный путь — ошибка без подмены. |
| `--socket PATH` | Подключиться к клиентскому сокету без автозапуска сервера. |

Без явных аргументов учитываются `HERDR_TAVERN_SESSION`, `HERDR_TAVERN_SOCKET_PATH`, `HERDR_TAVERN_CLIENT_SOCKET_PATH` и `XDG_CONFIG_HOME`. Старые `HERDR_*` не используются. При запуске сервера Tavern ставит встроенный Helpers первым в `PATH` и добавляет стандартные каталоги Cargo и Homebrew, но не читает настройки оболочки и не меняет окружение работающего сервера.

При запуске сервера Tavern также задаёт `PI_FORCE_IMAGE_PROTOCOL=kitty`, чтобы omp отображал изображения и в новых, и в восстановленных панелях. Настройку наследуют все панели этого сервера, в том числе при подключении других клиентов. Уже работающие серверы и процессы, включая серверы, доступные через `--socket`, не меняются: для применения настройки их нужно перезапустить с этой переменной.

## Настройка и работа

**Язык.** Открой настройки через `⌘,` или кнопку инструментов и выбери **English** или **Русский**. Начальный язык — английский; выбор сохраняется. Интерфейс обновляется сразу, без перезапуска Tavern, переподключения или потери herdr-сессий. Терминальный вывод и внешние программы сохраняют собственный язык.

**Агенты и звуки.** В разделе «Агенты» можно установить, обновить и удалить интеграции herdr; сами программы агентов и доступ к моделям настраиваются отдельно. После изменения интеграции перезапусти соответствующий агент. В разделе «Звуки» доступны выключатели, громкость, прослушивание и замена звуков своими файлами.

Элементы настроек используют выбранный звук интерфейсного клика с учётом общего выключателя, выключателя события, пользовательского файла и громкости. Все ползунки оформлены в бронзово-золотом стиле Tavern; при перетаскивании значение меняется сразу, а клик звучит один раз после отпускания. Прослушивание воспроизводит только выбранный звук, без дополнительного клика.

**Шрифт терминала.** Открой **Настройки → Терминал**: размер задаётся целым числом от **12 до 24 пт**, насыщенность — один из восьми уровней: **тонкая, сверхлёгкая, лёгкая, обычная, средняя, полужирная, жирная, сверхжирная**. Ступенчатый ползунок показывает название выбранного веса и поддерживает стрелки клавиатуры. По умолчанию — **16 пт, средняя насыщенность**. Предпросмотр показывает обычный, жирный и наклонный текст. Размер применяется по Return или при выходе из поля; кнопки изменения размера и ползунок насыщенности — сразу. **Вернуть по умолчанию** сбрасывает оба значения. Выбор сохраняется между запусками и обновляет основные и всплывающие терминальные поверхности без переподключения или перезапуска процессов панелей. Жирный текст программ использует Bold при основном весе до Semibold, ExtraBold при Bold и Heavy при ExtraBold. Heavy оставлен для выделения, поэтому разница насыщенности сохраняется во всём диапазоне. Подписи интерфейса и шрифты карточек не меняются.

При смене шрифта обновляются кэш глифов, границы рисунка и метрики композиции, затем запрашивается соответствующая геометрия терминала. Размеры ячеек округляются к пикселям экрана, в том числе при нечётном размере шрифта; переподключение использует выбранные метрики. Загруженные начертания удерживаются в памяти, поэтому изменение настроек не перечитывает файлы шрифтов.

**Конфигурация herdr.** Меню **herdr** позволяет менять доступные настройки, открывать полный `config.toml`, проверять и перезагружать его. Файл общий для локальных сессий. Темы и индикаторы herdr не меняют оформление Tavern; звуки Tavern настраиваются отдельно. При `--socket` меню всё равно работает с локальной конфигурацией, которая может отличаться от конфигурации подключённого сервера. Подробнее — в [документации herdr](https://herdr.dev/docs/configuration/).

**Вставка и файлы.** `⌘V` вставляет текст; прикрепление изображений зависит от программы внутри терминала. Перетаскивание из Finder вставляет пути в панель под курсором, без отправки Enter и без загрузки файлов.

**Разделение панелей.** `⌘D` разделяет панель в фокусе вправо, `⌘⇧W` — вниз. Новая панель получает фокус.

**Закрытие.** `⌘W` закрывает панель в фокусе после подтверждения завершения её процессов. Чтобы закрыть окно Tavern без завершения сессии herdr и её процессов, используй кнопку закрытия окна или команду меню «Окно».

**Уведомления.** Разрешение на баннеры задаётся в **Системные настройки → Уведомления → Herdr Tavern**. Отказ не отключает звуки и отметки непрочитанного на карточках агентов.

Tavern не воспроизводит весь интерфейс herdr: поддержка пользовательских `keys.command` не означает перенос всех встроенных сочетаний его терминального интерфейса.

## Разработка

Интерфейс написан на Swift/AppKit, клиент и выделенный протокол — на Rust. Исходники находятся в `app/` и `crates/`, проверки — в `tests/` и Rust-пакетах.

Навигация сравнивает упорядоченную проекцию отображаемых полей, подготовленную на потоке чтения и опубликованную с соответствующим состоянием. Геометрия поверхности отдельно обновляет захваты панелей; появление и закрытие модального листа меняют их доступность даже без терминального вывода. Новое соединение явно получает текущую геометрию, даже если она уже была вычислена во время открытия socket.

Материалы карточек используют точную геометрию в точках и пикселях, фоновую подготовку и общие часы 30 Гц. Отсутствующая точная карта по-прежнему рассчитывается синхронно вместо растягивания старой. Карточки за пределами видимой области освобождают свои ссылки на карты; переиспользуемые кэши сохраняют бюджеты 96 МиБ/72 GPU и 32 МиБ/48 CPU, которые не ограничивают память всего процесса.

Свет sidebar переиспользует заранее рассчитанные нормали исходной текстуры и кэширует точные сочетания панели, области и лампы (до 8 записей / 4 МиБ). Слои талисманов сохраняют прежние числа частиц и формулы движения, пропуская повторную запись неизменной статической геометрии и свойств частиц.

Снимки перетаскивания совместно фиксируют нативный текст, точную геометрию и параметры материала, затем читают результат GPU вне главного потока. Оригиналы остаются видимыми до готовности всей группы. Отпускание мыши во время захвата сохраняет точку отпускания, не забирая события следующего жеста; эта же точка определяет состав снимка — одну карточку или группу.

Чтение звуковых файлов и транзакции импорта/сброса выполняются на последовательном рабочем потоке; проверка AppKit и воспроизведение остаются на main. Воспроизведение копирует подготовленные шаблоны с кэшем до 8 записей / 32 МиБ закодированных данных — это не ограничение декодированной памяти NSSound. Импорт сохраняет прежний выбор до успешной проверки, копирования и безопасного удаления старого файла.

Исходящий JSON кодирует один последовательный writer. Объединяются только соседние, ещё не начатые команды resize; ввод и запросы сохраняют порядок и все callbacks. Новый лимит приёма намеренно не вводится: зависший сервер всё ещё может привести к росту исходящей очереди. На macOS прерванная запись в socket возвращает ошибку вместо завершения приложения сигналом SIGPIPE.

При запуске подготовка исходных Metal-ресурсов и поиск herdr выполняются на рабочих потоках; продолжение на main начинается только после обоих результатов. Provider исполняемого файла интеграций также работает на существующем последовательном worker; порядок подпроцессов и решения установщика сохранены.

Rust по-прежнему проверяет полную схему snapshot и сохраняет неизвестные необязательные поля в исходном JSON-значении. Входная строка и типизированная проверочная копия освобождаются до публикации, а metadata сериализуется сразу в принадлежащий событию вектор байтов; необходимая Swift-копия заимствованных FFI-буферов сохранена.

Видимость лампы хранится в одной точной текстуре `r32Float` на видимую карточку. Ключ включает материал, пиксельную геометрию и битовые представления геометрии сцены/XYZ лампы; мерцание и магический свет остаются динамическими. При промахе прежний расчёт видимости выполняется перед итоговым проходом в том же command buffer, без ожидания CPU. Итоговый шейдер читает тексель без фильтрации; скрытая карточка освобождает эту текстуру.

Не добавляй в Git локальные `.env`, приватные ключи и экспорты сертификатов с ключами (`.p12`/`.pfx`): они исключены через `.gitignore`, как и сборки и кэши. Для обезличенных примеров предусмотрены `.env.example` и `.env.sample`. Исключения не удаляют уже отслеживаемые файлы или данные из истории Git.

Из корня репозитория:

```sh
cargo +stable test --locked --workspace
```

Swift-проверки — самостоятельные драйверы, а не Xcode/XCTest-проект. Обновление выделенного протокола выполняется отдельно от обычной сборки; закреплённая ревизия и происхождение записаны в [PROVENANCE.json](../crates/herdr-protocol/PROVENANCE.json).

`ConnectionWriterTests` компилирует самостоятельную Rust-фикстуру Unix-сервера из release-зависимостей, уже подготовленных `./build.sh`, без скачивания зависимостей. Драйверам с детерминированными проверками рендеринга, рабочих потоков или аудио нужен `-D TAVERN_RENDER_TESTING`. Перед созданием представлений материалов драйверы ожидают `TavernCardSurfaceView.prepareResources` ограниченным по времени main runloop.

## Необязательная офлайн-подготовка ресурсов

Сохранённые художественные мастера находятся в `resources/Textures/Sources/`, `resources/Textures/TavernVisuals/sources/` и `resources/Icons/Sources/`. Подготовка ресурсов выполняется отдельно от обычной сборки и не обращается к сервису генерации изображений.

- `tools/prepare-{app-icon,button-families,sidebar-cabinet,scroller-material}.py` готовят иконку и используемые текстуры интерфейса; нужны Python 3 и Pillow.
- `resources/Textures/TavernVisuals/tools/prepare-selection.py` дополнительно требует NumPy и пишет три карты закладки непосредственно в `TavernVisuals/sprites/`.
- `resources/Textures/TavernVisuals/tools/prepare-chained-talismans.py` использует Pillow и пишет шесть RGBA-спрайтов непосредственно в `TavernVisuals/chained/`, без неиспользуемых карт высоты/материалов и demo-превью.

Запускай рецепт через `python3`, указывая путь относительно корня репозитория. Рецепты создают только изображения: JSON-манифесты не требуются и не записываются. Мастера доступны только для чтения, кроме явного импорта цепных талисманов с `--concepts DIR`: он копирует `talismans-chain-v1.webp` и требует отдельной актуализации сведений об источнике и правах в [NOTICE.ru](../NOTICE.ru). Это уведомление не предоставляет разрешение на распространение.

Рецепты не запускаются при сборке. В проверенном окружении рецепт закладки сохраняет прежнюю обработку, но не воспроизводит сохранённые PNG попиксельно; перед намеренной заменой готовых ресурсов сравните результат визуально.

## Оформление README

Текст шапки отрисован существующими шрифтами приложения, а не сгенерирован вместе с картинкой. Чтобы заново получить обе языковые версии, выполни из корня репозитория:

```sh
swift tools/render-readme-header.swift
```

Это необязательный инструмент оформления документации, не часть сборки приложения. Ему нужны сохранённый `docs/assets/header-art.webp` и существующие шрифты в `resources/Fonts/`. Уведомления о правах на шрифты и исходные ресурсы сохраняются: см. [NOTICE.ru](../NOTICE.ru).
